is **partially implemented**, and what is **not implemented**. It deliberately
separates the user's 7.1 targets from what this source tree actually contains.

command named next to it.

## What is implemented in this slice

### 1. Completion update
- `package.json` is `7.1.0`; `scripts/check.js` enforces that version.
- `docs/specialists-7.1.json` is generated by `npm run bench:specialists`.
- `docs/retrieval-7.1.json` is generated by `npm run bench:retrieval`.
- This ledger and the progress log are updated with measured values.

### 2. Neural intelligence (partial)
Implemented and tested:
- Four additional specialists: `semantic`, `context`, `failure`, plus temperature
  calibration shared by all seven specialists.
- 1,852 new authored items in `core/ml/data/specialists-ext.js`; group-aware
  splits keep scenario families out of the test fold.
- `core/ml/calibration.js`: temperature scaling, ECE and Brier score. Calibration
  changes confidence only; it never changes a predicted label.
- `SpecialistZoo.crossValidate()` performs deterministic 5-fold group-disjoint
  cross-validation.
- Brain memory/context reranking and dispatcher failure advisory use promoted
  models when present; absent models degrade to the deterministic path.
- 7 specialist tools, HTTP prediction for `semantic|context|failure`, and CLI
  commands for the three new models.
- Seven-model benchmark in `docs/specialists-7.1.json`.

Measured (single 5-fold run, CPU):
`tools 0.8734 vs 0.7722 · routing 0.8936 vs 0.8085 · relevance 0.975 vs 0.6833 ·
complexity 0.9 vs 0.825` on 79/47/120/40 cases. Held-out single split:
`semantic 0.7625 vs 0.675`, `context 1.0 vs 0.5556`, `failure 0.7153 vs 0.6667`.
Calibration: semantic ECE 0.0901 → 0.0543 (T=0.75), failure 0.1941 → 0.1634
(T=1.3). This is synthetic authored data, not production traffic.

Not implemented: learned attention, adaptive cognitive routing beyond the
existing heuristics, optional GPU tensor acceleration, MoE routing, compact
generative transformers. The project has classifiers, not a generative LM, and
we do not call a classifier one.

### 3. Training (partial)
Existing lab behavior is preserved: gated experiments, immutable base weights,
checkpoint/artifact hashes, named approval for promotion and rollback.
Not implemented: real LoRA/QLoRA/distillation/preference training against
external ML runtimes, resource estimation for those runs, experiment queues,
cancellation of an external trainer, HPO and training curves.

### 4. HyperCore (not extended in this slice)
The existing blackboard, contradiction records, goals and attention budget are
unchanged. Conditional executor branches and durable task semantics were
extended instead (see §6).

### 5. Unified retrieval (new, partial)
`core/retrieval/unified.js` implements:
- BM25 lexical scoring, hashed-vector cosine, graph-group proximity and
  reciprocal-rank fusion (0.55 / 0.35 / 0.10);
- optional semantic and reranker boosts from promoted checkpoints;
- per-stage provenance and `benchmark()` returning nDCG@k, MRR, recall@k and
  p50/p95 latency;
- `benchmarkFromRelevanceData()` over the authored graded set (64 documents, 48
  queries).

Measured (`docs/retrieval-7.1.json`, k=3):
`lexical NDCG 0.4683 / MRR 0.5538 · vector 0.4407 / 0.5434 · hybrid 0.4704 /
0.5451 · neural 0.5040 / 0.6049`. The neural mode is measured with checkpoints
trained in a temporary home. Hybrid is only marginally better than lexical and
its MRR is worse; that is reported, not hidden. The corpus is a 64-document
smoke-scale set, not a production search log.

Not implemented: entity resolution, multi-hop question decomposition, PDF/DOCX/
spreadsheet ingestion for this retriever, incremental indexing, citation
validation, scoped export/import, and wiring the retriever into the main chat
memory path. GraphRAG's existing graph remains separate.

### 6. Executive engine (partial)
Implemented in this slice:
- **Conditional steps**: `when` supports `all/any/not`, `exists`, `eq/neq`,
  `truthy/falsy`, `contains`, `gte/lte` over typed results, with no `eval`.
  A condition-skipped step records `conditionSkipped`, does not block its
  dependents and is visible in the finished task.
- Existing durable task state, retries, approvals, cancellation propagation,
  crash reconciliation and replanning are unchanged.
- Tests cover false and true branches, nested `all/not`, and the dependency
  behavior.

Not implemented: per-step deadline scheduling beyond the task deadline,
persistent worker pools and a priority work queue, transactional multi-step
state, restart tests for every external side effect. No claim is made that the
executor can resume a half-executed write.

### 7. Agents (not extended)
There are still 31 agents. The 89-agent target was not met. Creating placeholder
agents would violate the no-fake-agents constraint, so none were added.

### 8. Tool ecosystem (partial)
Added 5 calendar capabilities, so the audit reports **350 tools / 29 categories**.
All 350 pass structural validation; **86** were executed by the audit with safe
arguments, **264** remain unexecuted. Deep tests exercise the calendar and
specialist tools directly. Semantic discovery, typed composition, dependency
graphs and quota/cancellation semantics for tools are not newly implemented.

### 9. Phone/communication (not extended)
No live call was made. Existing mock-provider tests and the "never claim a real
call" guard are unchanged. Bidirectional audio streaming, SIP, turn-taking,
interruption handling and scheduled call workers remain unfinished.

### 10. Assistant (partial)
- New `core/calendar.js`: dependency-free RFC 5545 VEVENT import/export,
  UID-based updates, deterministic IDs, bounded DAILY/WEEKLY/MONTHLY recurrence
  (INTERVAL/COUNT/UNTIL, BYDAY for weekly), duration/interval validation, 2 MB
  and 5,000-event limits, per-event errors and honest `TZID` labelling.
- Calendar is wired into the agent, daily briefing, five tools, CLI
  (`sentinel calendar …`), HTTP (`GET /api/calendar`,
  `POST /api/calendar/event`, `POST /api/calendar/import`) and the UI lab card.
- Windows notifications, alarms, snooze, quiet-hour escalation and a proactive
  rule editor are unchanged/not added.

### 11. Coding intelligence (not extended)
Parser-backed ASTs, transactional multi-file patches, refactoring and isolated
regression verification remain on the existing implementation and were not
expanded in this slice.

### 12. Performance/hardware (not extended)
No GPU, live Ollama or RTX 4060 Ti measurement was possible in this environment.
The existing mock and CPU measurements are labelled as such; no GPU number is
invented.

### 13. Multimodal/device (not extended)
No microphone, wake-word, OCR or real Android/ESP32 device test was run.

### 14. Security/self-healing (unchanged)
Existing approval binding, auth, sandbox policies and recovery journals are
untouched. No fault injection was added for full disk, corrupt DB or interrupted
migration in this slice.

### 15. UI (partial)
- The lab panel now reads `/api/calendar?days=7` and shows real event counts and
  the next three events, alongside the existing real specialist card.
- No fake activation or progress is displayed. The centered prompt, streaming,
  history and STOP behavior are unchanged.

### 16. Testing (partial)
- Deep suite: **160** checks (was 157), including 7-model training, calibration
  math, group-disjoint splits, conditional executor branches, unified retrieval
  fusion/provenance/benchmark, calendar ICS/recurrence and briefing composition.
- New `test/properties.js`: **5 seeded property checks** over calendar
  invariants, recurrence COUNT, ICS round-trip, retrieval score bounds and
  percentile monotonicity. It is part of `npm test` and CI.
- Total checks: **351** (23 behaviour + 25 assistant + 48 UI + 160 deep + 5
  property + 90 evaluation). The 2,000-check target is not met.
- Mock/deterministic results remain separated from live/hardware results; none
  of the new tests claim a live model or a real call.

### 17. Delivery
- Exactly one `INSTALL_SENTINEL_FULL.ps1` is preserved and was not executed.
- No EXE/APK/AAB/MSI/firmware/binary was produced or published.
- Source CI is the only delivery path; property tests were added to the Linux
  workflow. Windows CI was not available in this sandbox and is not claimed.
- `PR #1` remains open and must not be merged.
